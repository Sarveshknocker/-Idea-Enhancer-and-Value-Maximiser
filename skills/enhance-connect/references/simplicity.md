# Simplicity filter: "solve complex problems simply"

Complex problems rarely need complex products. They need the **one leverage point** handled extremely well.

## Tests (a candidate must pass at least 4 of 6)
1. **5-minute value**: a new user gets a real benefit within 5 minutes, without training.
2. **6-week ship**: a small team (1–3 people) can ship a usable first version in ≤ 6 weeks, reusing existing components.
3. **Fewer steps**: it removes steps, decisions or tools from the user's day. It doesn't add them.
4. **One-sentence explanation**: a 12-year-old could explain what it does.
5. **Works on existing infrastructure**: runs on devices, apps and channels users already have (phone, WhatsApp, browser, existing ERP).
6. **Graceful degradation**: still useful if the fancy part (AI, sensor, network) fails.

## Simplification moves
- **Remove**: what happens if we delete this feature/step entirely?
- **Default**: replace choices with smart defaults.
- **Reuse**: an open-source project, API or existing platform does 80 % of this, so wrap it.
- **Human-in-the-loop first**: do it manually/concierge for the first 20 customers, automate what repeats.
- **Narrow**: one segment, one use case, one geography first; expand later.
- **Channel-native**: meet users inside the tool they already use (WhatsApp, Excel, Slack, Tally, Shopify).
- **Leverage point**: find the single variable that moves the outcome most (often information timing, trust, or coordination) and attack only that.

## Complexity budget
Each concept gets a budget: at most **3 core features** in v1, **1 new habit** asked of the user, **1 integration** required to start. Anything beyond that goes to the "later" column of the roadmap.
