# Moats: designing defensibility into v1

| Moat | Built by | v1 design move |
|---|---|---|
| **Proprietary data** | Every interaction produces data others can't get | Capture structured outcome data from day one (with consent); feed it back as better predictions for users |
| **Network effects** | Each new user makes it more valuable for others (direct, two-sided, data, local) | Seed one dense local network (a city, a college, a trade association) before expanding |
| **Switching costs** | Workflows, integrations, history, trained models live in your product | Become the system of record for one critical workflow; offer easy import, make history valuable |
| **Brand & trust** | Reliability, transparency, community, certification | Public guarantees, transparent pricing, visible reviews, founder presence in communities |
| **Distribution** | Exclusive/strong channel partnerships, embedded placements | Partner with the institution users already trust (co-ops, banks, associations, marketplaces) |
| **Regulatory / licenses** | Approvals that take time (fintech, health, drones, telecom) | Start compliant; treat compliance as a feature for enterprise buyers |
| **Cost advantage** | Better tech, scale, or unique supply | Reuse open source & shared infra; aggregate demand to get better supplier terms |
| **Community & ecosystem** | Contributors, creators, integrators build on you | Open APIs/templates; recognise and reward contributors |
| **Speed of learning** | Faster iteration than incumbents | Weekly releases, tight feedback loops, instrumented experiments |

Anti-moats to avoid: features anyone can copy in a week, dependence on a single platform's API or policy, paid ads as the only growth channel.
